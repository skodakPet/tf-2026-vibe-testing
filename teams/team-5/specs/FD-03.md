# FD-03 · Restaurant menu
Seed: none — each test starts with page.goto('/')

UI names seen in the live app (names only, not expectations):
- Home: restaurant cards are links named after the restaurant; `Burger Palace` -> `/restaurant/1`.
- Restaurant page: h1 `Burger Palace`; paragraph with cuisines (`American, Burgers`); description
  paragraph; promotion label (`20% OFF orders over $25`); rating (`4.8`) with `(1234 reviews)`;
  time range (`25-35 min`); address; label `Delivery Fee` with value (`$2.99`).
- Menu: `tablist` with tabs `Burgers` (selected by default), `Sides`, `Drinks`; each has a `tabpanel`
  of the same name.
- Each dish is a link to `/product/<id>` (e.g. `Classic Beef Burger` -> `/product/bp-1`,
  `Truffle Fries` -> `/product/bp-5`) containing h3 with the dish name, a description paragraph,
  a price (`$12.95`) and an icon-only button (the quick-add, nested inside the dish link).
- Header: button `Cart`; after adding, its name becomes `Cart 1` (badge with the count).
- Toast after quick-add: `Added to cart!` / `<dish> has been added to your cart.`
- Dish page: h1 with the dish name, button `Add to Cart - $<price>`.

## FD-03.1 · Page shows name, cuisines, rating, delivery time, delivery fee, promotion
Spec quote: "the restaurant's name, cuisines, rating, delivery time, delivery fee and promotion;"
Steps:
1. Go to `/`.
2. Click the `Burger Palace` restaurant card link.
3. Check that the URL matches `/restaurant/<id>` (here `/restaurant/1`).
4. Check the page shows:
   - the restaurant name as h1 (`Burger Palace`),
   - the cuisines (`American, Burgers`),
   - a rating (a number such as `4.8`),
   - a delivery time (pattern `<n>-<m> min`),
   - a delivery fee (a price `$<n>.<nn>` or `Free`),
   - the promotion text (non-empty; `Burger Palace` has one).
Expected (from spec): The restaurant page shows the restaurant's name, cuisines, rating, delivery time, delivery fee and promotion.

## FD-03.2 · Menu grouped into category tabs
Spec quote: "the menu, grouped into category tabs (for example *Burgers*, *Sides*, *Drinks*);"
Steps:
1. Go to `/`, open `Burger Palace`.
2. Find the menu `tablist`; check it contains the tabs `Burgers`, `Sides`, `Drinks`.
3. Note which tab is selected and the dish names in the visible `tabpanel`.
4. Click tab `Sides`; check it becomes selected and the visible `tabpanel` shows a different set of
   dishes than step 3 (no dish from the `Burgers` panel).
5. Click tab `Drinks`; repeat the check.
Expected (from spec): The menu is grouped into category tabs (e.g. *Burgers*, *Sides*, *Drinks*); each tab shows the dishes of its own category.

## FD-03.3 · Each dish: name, description, price, quick-add + button
Spec quote: "for each dish: name, short description and price, and a quick-add **+** button."
Steps:
1. Go to `/`, open `Burger Palace`.
2. For every tab (`Burgers`, `Sides`, `Drinks`): click it, then for every dish link in the visible
   `tabpanel` check that it contains:
   - a name heading (h3, not empty),
   - a short description (non-empty paragraph),
   - a price (pattern `$<n>.<nn>`),
   - a quick-add button.
3. Check the number of quick-add buttons equals the number of dishes in the panel.
Expected (from spec): Every dish shows its name, short description, price and a quick-add **+** button.

## FD-03.4 · Quick-add adds one dish, confirms it, header cart count +1
Spec quote: "Quick-add puts one of that dish into the cart and confirms it. The cart count in the header goes up by one."
Steps:
1. Go to `/`, open `Burger Palace`.
2. Read the header cart count (button `Cart`; no badge = 0).
3. In tab `Burgers`, click the quick-add button of `Classic Beef Burger`.
4. Check the URL is still `/restaurant/1` (quick-add must not open the dish page).
5. Check a confirmation appears that names the dish (e.g. toast mentioning `Classic Beef Burger`).
6. Check the header cart count is previous count + 1 (here `1`).
7. Click the quick-add of `Classic Beef Burger` again; check the count is + 1 again (`2`).
8. Open the cart (button `Cart`) and check `Classic Beef Burger` is there with quantity 2
   (one per quick-add).
Expected (from spec): Each quick-add puts one of that dish into the cart, the app confirms it, and the cart count in the header goes up by one.

## FD-03.5 · Selecting the dish opens its detail page (FD-04)
Spec quote: "Selecting the dish itself opens its detail page (FD-04)."
Steps:
1. Go to `/`, open `Burger Palace`.
2. Click tab `Sides`, then click the dish name `Truffle Fries` (not the quick-add button).
3. Check the URL matches `/product/<id>` (FD-04: "The dish page (`/product/<id>`)").
4. Check the dish page shows h1 `Truffle Fries`.
5. Check the header cart count did not change (selecting a dish does not add it).
Expected (from spec): Selecting the dish itself opens its detail page (`/product/<id>`, FD-04) for that dish.

## FD-03.6 · Every button has an accessible name, incl. icon-only quick-add
Spec quote: "Every button can be used with a screen reader: each one has an accessible name that says what it does, including icon-only buttons such as quick-add."
Steps:
1. Go to `/`, open `Burger Palace`.
2. For every tab (`Burgers`, `Sides`, `Drinks`): click it, then collect all visible elements with
   role `button` on the page.
3. For each button check its accessible name is not empty.
4. For each quick-add button check its accessible name says what it does and identifies the dish
   (e.g. contains "add" and the dish name).
5. Click one quick-add so the confirmation toast appears; repeat step 3 for the buttons inside the
   toast (e.g. its close button).
Expected (from spec): Every button has an accessible name that says what it does, including icon-only buttons such as quick-add.
App shows: quick-add buttons have no accessible name (role `button` with empty name, 4 in `Burgers`, 3 in `Sides`); the close button in the `Added to cart!` toast also has no name.
