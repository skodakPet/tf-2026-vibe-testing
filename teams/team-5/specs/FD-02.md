# FD-02 · Search and filter
Seed: none — each test starts with page.goto('/')

UI names seen in the live app (names only, not expectations):
- Search box: textbox with placeholder/name `Search for restaurants or dishes...`.
- Button: `Search` (right next to the search box).
- Cuisine chips (buttons, in this order): `All`, `Pizza`, `Burgers`, `Sushi`, `Italian`, `Mediterranean`.
- Result list: under the h2 `Popular Restaurants`. Each card is a link named after the restaurant
  (`href` = `/restaurant/<id>`), with an h3 name and a cuisines paragraph.
- Restaurants on `/` with no search and no chip (5 cards):
  `Burger Palace` (American, Burgers), `Mediterranean Delight` (Mediterranean, Healthy),
  `Pizza Corner` (Italian, Pizza), `Sushi Masters` (Japanese, Sushi), `Koliba u Jána` (Slovak).
- Empty state: two paragraphs in place of the cards (text is checked from the spec, see FD-02.6).
- The URL stays `/` while searching and filtering.

## FD-02.1 · Search finds by restaurant name or dish name
Spec quote: "The search box finds restaurants by **restaurant name** or by **dish name**. *"Classic Beef"* finds the restaurant that serves the Classic Beef Burger."
Steps:
1. Go to `/`.
2. Fill the search box `Search for restaurants or dishes...` with `Classic Beef` (a dish name).
3. Read the names (h3) of all cards under `Popular Restaurants`.
4. Check that `Burger Palace` is in the list (the restaurant that serves the Classic Beef Burger — confirm by opening `/restaurant/1` if needed; that is FD-03 territory, so keep it optional).
5. Clear the search box and fill it with `Sushi Masters` (a restaurant name).
6. Check that `Sushi Masters` is in the list and that restaurants whose name and dishes do not contain "Sushi Masters" (for example `Pizza Corner`) are not.
Expected (from spec): Searching a dish name (*Classic Beef*) shows the restaurant that serves the Classic Beef Burger. Searching a restaurant name shows that restaurant.

## FD-02.2 · Search ignores upper and lower case
Spec quote: "Search ignores upper and lower case: *burger* and *BURGER* give the same result."
Steps:
1. Go to `/`.
2. Fill the search box with `burger`. Store the list of card names (h3) under `Popular Restaurants`.
3. Clear the search box and fill it with `BURGER`. Store the list of card names again.
4. Compare both lists: same names, same count. The list must not be empty (otherwise the test proves nothing).
5. Optional extra pair on a dish name: `classic beef` vs `CLASSIC BEEF` — lists must be equal.
Expected (from spec): *burger* and *BURGER* give the same result.

## FD-02.3 · Results update while typing; Search button gives the same result
Spec quote: "Results update while the customer types; pressing **Search** gives the same result."
Steps:
1. Go to `/`. Store the list of card names (5 cards).
2. Click the search box and type `burger` key by key (`pressSequentially`, not `fill`). Do NOT press Enter or click `Search`.
3. Check that the card list has changed without any button press (it no longer shows all 5 cards; it shows only matching restaurants). Store the list as `typedResult`.
4. Click the `Search` button.
5. Store the list as `buttonResult` and compare it with `typedResult`.
Expected (from spec): The list updates while typing, before any button press. Pressing **Search** gives the same result as the list shown while typing.

## FD-02.4 · Cuisine chips show only that cuisine; All shows every restaurant
Spec quote: "The cuisine chips (**All**, **Pizza**, **Burgers**, **Sushi**, **Italian**, **Mediterranean**) show only restaurants serving that cuisine. **All** shows every restaurant. Not every cuisine has a chip; **All** is the only view guaranteed to show every restaurant."
Steps:
1. Go to `/`. Store the full list of card names (baseline, 5 cards).
2. Check that the chips `All`, `Pizza`, `Burgers`, `Sushi`, `Italian`, `Mediterranean` are visible.
3. For each chip `Pizza`, `Burgers`, `Sushi`, `Italian`, `Mediterranean`:
   1. Click the chip.
   2. Check that at least one card is shown.
   3. Check that every shown card's cuisines paragraph contains the chip's cuisine (e.g. `Pizza` → every card lists `Pizza`).
   4. Check that restaurants from the baseline that do not list that cuisine are not shown (e.g. `Pizza` → no `Burger Palace`, no `Sushi Masters`).
4. Click `All`.
5. Check that the card list equals the baseline: all 5 restaurants, including `Koliba u Jána` (Slovak — a cuisine with no chip).
Expected (from spec): Each cuisine chip shows only restaurants serving that cuisine. **All** shows every restaurant, including those whose cuisine has no chip.
Note: in the live app, clicking a chip writes the cuisine name into the search box. The spec says nothing about this, so the test must not depend on it (see FD-02.5).

## FD-02.5 · Search and cuisine chip apply together
Spec quote: "A search and a selected cuisine chip apply **together**: with **Pizza** selected, searching *burger* shows only restaurants that match both."
Steps:
1. Go to `/`.
2. Click the `Pizza` chip.
3. Fill the search box with `burger`.
4. Read the shown card names and their cuisines paragraphs.
5. Check that every shown card lists `Pizza` in its cuisines AND matches `burger` (name or dish).
6. Check that `Burger Palace` (American, Burgers — not Pizza) is NOT shown.
7. If no card matches both, the empty state from FD-02.6 is an acceptable result.
8. Reverse order as a second check: go to `/`, fill `burger` first, then click `Pizza`; apply the same checks as in steps 5–6.
Expected (from spec): With **Pizza** selected, searching *burger* shows only restaurants that match both the Pizza cuisine and the search *burger*.
App shows: The chip and the search box do not combine. With `Pizza` selected, filling `burger` shows `Burger Palace` (not a Pizza restaurant). With `Sushi` selected, `burger` also shows `Burger Palace`; clearing the search then shows all 5 cards although `Sushi` was clicked. In reverse order, clicking `Pizza` after `burger` replaces the search text with `Pizza` and shows only `Pizza Corner`.

## FD-02.6 · No match shows *No restaurants found* with a hint
Spec quote: "When nothing matches, the page says so — *No restaurants found* — with a hint to try another search or filter."
Steps:
1. Go to `/`.
2. Fill the search box with a term that matches no restaurant or dish, e.g. `zzzqqq`.
3. Check that no restaurant card (link to `/restaurant/...`) is shown under `Popular Restaurants`.
4. Check that the text `No restaurants found` is visible.
5. Check that a hint is visible next to it that suggests trying another search or filter (match loosely: text contains "search" and "filter"; do not hard-code the exact hint sentence, the spec does not give it).
Expected (from spec): The page says *No restaurants found* and shows a hint to try another search or filter.

## Otevřené otázky
- FD-02.5: spec says "match both" but does not say which restaurant (if any) should be shown for Pizza + *burger*. Plan accepts either Pizza-cuisine cards that match *burger* or the empty state. Dopad: the test cannot assert an exact list. Kdo odpoví: product owner / spec author.
- FD-02.1: "Classic Beef Burger belongs to Burger Palace" comes from the live app (card list after search), not from the spec. The spec only says "the restaurant that serves the Classic Beef Burger". Dopad: the test hard-codes `Burger Palace`; optional step 4 can confirm it via the menu. Kdo odpoví: test author (team-5).
